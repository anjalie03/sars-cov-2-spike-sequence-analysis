# Results/Tables

Result tables generated by the notebook `spike_protein_variant_analysis.ipynb` from the SARS-CoV-2 spike sequence analysis. The dataset has 10 sequences: the Wuhan reference (`Reference_WuHan`, 1273 aa) plus three Alpha, three Delta, and three Omicron sequences.

## Files

| File | Rows | Description |
|------|------|-------------|
| `mutations.csv` | 287 | One row per amino acid difference from the reference. Columns: `sample`, `lineage`, `position`, `ref` (reference residue), `alt` (residue in the sample), `mutation` (e.g. L229X) |
| `pairwise_vs_reference.csv` | 9 | Pairwise alignment of each sequence against the reference. Columns: `sample`, `score` (alignment score), `identities`, `mismatches`, `gaps`, `percent_identity` |
| `sequence_stats.csv` | 10 | Per-sequence properties. Columns: `sample`, `length` (aa), `mol_weight_Da`, `isoelectric_point`, `instability_index`, `gravy_hydrophobicity` |

## How these were made

- Sequences come from the alignment in `data/processed/spike_aligned.fasta`.
- Tables were created with Biopython and pandas and saved with `df.to_csv(...)`.
- Re-running the notebook from the top regenerates all tables.

## Notes

- Reference sequence: `Reference_WuHan`, 1273 aa. It is excluded from `pairwise_vs_reference.csv` because it is the comparison target.
- Percent identity is calculated over the 1273 reference positions.
- Some entries in `mutations.csv` have `alt` = X, meaning an unknown or ambiguous residue in the input sequence. These are not confirmed substitutions, so filter them out before counting true mutations.
- Mutation positions are numbered ADD (reference residue numbering or alignment column).
